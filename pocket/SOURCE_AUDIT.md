# Source audit and implementation decisions

Upstream PokeDaisy: lidor30/pokedaisy at a64c9172828bb2e3824d5211655091e27f7ff73c.
Pinned mGBA: 26b7884bc25a5933960f3cdcd98bac1ae14d42e2 (upstream 0.10.5).

## Reused directly

- `3ds/core`: software canvas, Pixel Operator glyphs, styles, Gen 3 ROM detection,
  memory snapshots, icons decoded from the user's ROM, party, summaries, bag,
  battle, map, dex, guide and card renderers and their recorded interaction regions.
- `3ds/desktop/pd_png.c`: actual framebuffer capture, no external image framework.
- mGBA's original core API, video, blip audio, input, save and state functions.
- GPL and attribution notices, mGBA and third-party licenses.

The existing portable host was 3DS-specific: GPU framebuffers, NDSP audio,
libctru input, dual displays, stylus navigation and `sdmc:` paths. None of those
platform APIs are used in the new host. The Android application requires Kotlin,
Compose and JNI; it cannot execute unchanged on this Linux handheld.

## Adapted from Android

- `Gen2Reader.kt`: Polished Crystal's fixed-bank WRAM addresses and 48-byte
  party structs; same addresses across 3.2.0 through 3.2.3. Forms, egg flag,
  gender, level, HP, status, moves and PP follow the upstream logic.
- `Gen2SpeciesPolishedCrystal.kt`: variant-form lookup and gender ratios.
- `Gen2PolishedCrystalGen.kt`: exact per-build SHA-1 keys and art-table addresses.
- `SpeciesNamesPolishedCrystal.kt`, `MoveDataPolishedCrystal.kt`, species types
  and type names: C tables generated by `gen_polished.py`, including faithful
  overrides rather than using retail GBA move IDs.
- `Gen2Art.kt` / `Gen2Dex.kt`: mini-icon pointer layout, palettes, bank addressing
  and Polished Crystal's LZ repeat-length differences.
- `PartyScreen.kt`: white/black Crystal palette, selected gray row, gold HP label,
  green/amber/red HP bar. Pixel Operator is used as the current portable fallback.
- `pokedaisy_jni.c::pk_gb_read_banked`: direct WRAM bank access, independent of
  the currently selected emulated SVBK register. No memory writes in release code.

## New platform code

`pocket/main.c` owns SDL video/audio, game selection, physical input, pause/resume,
frame pacing, integer scaling, safe save paths and backups, state confirmations,
clean exit and a game menu. GBA UI navigation focuses upstream hit regions and
activates the existing actions. There is no mouse cursor or permanent split view.
`pocket/polished.c` adapts the Android party path; it is a limited port of those
features, not the complete Android Compose UI.

The only changes to `3ds/core` are conditional `POCKET_NATIVE` labels for the
ROM folder and hiding the 3DS-only stretch/1.5x setting. Original 3DS behavior is
preserved when that define is absent.

## Initial Phase 1 limits (historical)

Only Party/Summary is ported for Polished Crystal. Android's broader data readers,
Compose navigation, font extraction, held-item markers and other sections still
need adaptation. DS, RetroAchievements, cloud and network features are excluded.
ROM archives, automatic save migration, rewind and NextUI power/suspend integration
are not implemented. Commercial ROM validation and hardware testing remain the
highest priorities.

## Display hotfix

Gameplay now shares the opaque RGB888 presentation path with the companion.
The supplied 3.1.1 ROM was tested with no memory-fixture injection on native Linux
and ARM/QEMU. No 3.1.1 companion support was added; upstream's 3.2.x compatibility
remains the requirement for party data. Physical display verification is pending.

## Phase 2: gameplay scaling and inventory

The user confirmed the Phase 1 display hotfix, live party and ROM sprite on the
physical Brick, with photos. This is user-reported hardware validation, not a
claim of physical testing by the developer.

Gameplay uses a separate RGB888 texture at the native game dimensions and a
physical-pixel destination rectangle. Nearest filtering and no blending preserve
the working opaque color path. The companion retains its 512x384 logical canvas.
Screenshots allocate their readback buffer from the actual renderer output size,
so a 1024x768 capture cannot overflow a 512x384 buffer.

The Bag directly adapts `Gen2Reader.kt::readGen2Bag`, including all four counted
lists, the zero-terminated key-item list, and TM/HM bits. Medicine is merged into
Items as in Android. All lists must be well formed before the Bag is exposed.
`ItemNamesPolishedCrystal.kt` supplies item and faithful-build names.

The shared C snapshot adds optional held-item/EXP fields and increases pocket
capacity to 128 so all 75 Items plus 37 Medicine entries fit without truncation.
The existing GBA decoder and screens are otherwise unchanged. Summary decoding
follows upstream party offsets; held-item markers reuse `Gen2Art.holdIcons`.
No inventory use, ROM writes, save migration, or guessed 3.1.1 offsets are added.


## Phase 3: extend the companion and reduce duplicate definitions

Fetched origin/main again: still a64c9172828bb2e3824d5211655091e27f7ff73c.
`Gen2Reader.kt::decodePolishedBattleMon/readGen2Telemetry/readGen2PokedexState`
provide the battle structs, foe party, flag mapping and caught-implies-seen rule.
`Gen2Dex.kt` provides ROM text/Huffman decoding, item/TM descriptions, entry
pointers, category/body/base stats and column-major front-pic placement. These
are adapted with bounds and corrupt-stream limits; no ROM text/art is bundled.

RAM addresses, dex order and character map now generate from upstream rather
than duplicating constants in the host. Input hashes and --check flag stale
outputs. `pc_ui_input/pc_ui_draw` own game-specific navigation, leaving the SDL
host responsible for emulator and physical controls. UPSTREAM.md documents the
update contract and remaining manual algorithm/UI work. Pocket CI is prepared;
no remote CI or fork creation is claimed.


## Phase 4: supported personal ROM and Android presentation

The supplied unmodified 3.2.3 cart matches upstream SHA-1
6930b48af5844d373e3c9130f26d6dd1084cf4ed. All 289 entry texts/front pictures,
373 item/TM/key descriptions and three town-map tilemaps decode successfully.
The original font maps Gen2Art.POLISHED_CHARS to its ROM FontNormal bytes; no
TTF dependency or extracted graphics are installed. The portable canvas adds a
small opt-in scoped font hook; every companion draw restores the default.

Gen2Art.townMap/player provide the map's tile flips, palettes and player sprite.
MapSecDataPolishedCrystal supplies landmarks and map/group lookup. Gen2Reader's
map and backup-map rule supplies the live location. MonDetailScreen supplies
the two-column information/moves hierarchy; TypeChartPolishedCrystal supplies
defensive matchups. Gen2Dex.flow supplies broken-word and compound handling.

The optional test_rom executable runs only normal controller presses through
mGBA, from a fresh game to Cyndaquil. No poke/injection, ROM modifications or
external save is used. Its source and the button script are included, while
ROM, private RAM dumps, battery saves and savestates are excluded. The install
binary contains none of this test route or test-only environment handling.

GitHub work was deferred at the user's request. No fork or push was made.

## Phase 7 quick menu

Quick-menu behavior and pixel art adapted from Android QuickMenu.kt, QuickMenuSettings.kt and FieldHud.kt. Linux evdev button ordering was checked against SDL release-2.26.0 src/joystick/linux/SDL_sysjoystick.c ConfigureJoystick. SDL controller bindings take precedence, then explicit POCKET_L3_BUTTON/POCKET_R3_BUTTON overrides. Actual NextUI driver discovery still needs hardware verification. R3 display cycling and a Polished expansion adapter are added in Phase 8.

## Phase 8 Polished overworld

Reuse `app/src/main/cpp/pk_wide_gb.c`; native-only definitions leave Android game selection unchanged. Official v3.2.3 release symbols are pinned by SHA256 in `gen_polished_wide.py`; generated output contains addresses and identity only, no ROM graphics. Differences from retail Crystal: 7-byte headers, compressed map blocks, separate WRAM banks for 4096-byte metatiles/attributes, 34-byte loaded objects, packed 4-byte sprite headers and 1326-byte overworld buffer. Reuse the existing bounded Polished LZ codec. No writes to ROM, party, bag, events or map state. The host caches a render per emulated frame and clears it on state load. Only verified normal 3.2.3 expansion is enabled.

## Phase 9 companion completion pass

`PokedexScreen.kt` DexFilter/entries supplies exact ALL, CAUGHT, SEEN ONLY (excluding caught), NOT SEEN predicates. Filtered rows retain canonical Polished dex numbers and original ordering. `BattleInfoScreen.kt`/TypeChartUtil supplies weakness, resistance and immunity grouping/sorting; the native page uses actual battler types. `GuideScreen.kt` excludes eggs for party-best level and compares the maximum upstream badge-adjusted boss-team level. Existing original font, palette and native canvas are retained. These changes read snapshots only.

## Phase 10 integration audit

Reviewed upstream 1.3.1 changes through 54d8f4867501feb32b7ee139a5616b7c6301f044. Merged the original source history. Reused pk_savevf.c unchanged, with Pocket's independent host wrapper retaining read/write-only save admission and making I/O errors visible. Did not enable Android MAKEOVER, DS or new GBA companions. Per-game display settings follow ROM SHA-1 and are atomic separate config files. The SHA-1 codec was moved unchanged from polished.c into rom_identity.h. GuideScreen bossPage and GuideUiState.tap now map to separate selected Pokemon entries rather than revealing a whole team. Single-entry reveals close on entry/page/progress changes.

## Phase 11 source audit

Inspected PartyScreen SlotGeometry, drawSlotFrame/drawHpBar, Polished palette and ten-frame bob; MonDetailScreen SummaryBar/ExpBlue; SnapshotView.expProgress; ExpTables; Gen2SpeciesPolishedCrystal growth rates; Gen2Reader.curBattleMon; SuggestionsScreen OUT behavior. Polished rates 0/1/2/3 map to upstream tables 0/3/4/5. Native OUT uses the upstream party index definition rather than species/level matching, avoiding ambiguity for duplicate party members. No ROM writes or invented offsets are added. PokedexScreen has no name search and Gen 2 PartySlot has no EXP bar; earlier checklist assumptions were corrected.
